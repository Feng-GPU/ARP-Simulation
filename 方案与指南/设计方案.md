# ARP 地址解析协议仿真软件设计方案

## 1. 项目概述

### 1.1 项目名称

ARP 地址解析协议仿真软件

### 1.2 设计目标

在一个虚拟局域网中模拟 ARP（Address Resolution Protocol，地址解析协议）的完整工作过程，直观展示：

- 主机发现目标 IP 对应 MAC 地址时发送 ARP 请求广播；
- 目标主机接收请求后发送 ARP 应答单播；
- 各主机通过接收报文进行被动学习；
- ARP 缓存表的新增、更新、命中和老化删除；
- 多线程主机节点和共享消息队列对局域网通信的抽象。

本项目只模拟协议行为，不访问真实网卡，不发送真实 Ethernet 帧，也不修改操作系统 ARP 缓存。

### 1.3 技术栈与运行方式

| 项目 | 选择 |
|---|---|
| 编程语言 | Python 3.12+ |
| 图形界面 | PySide6 |
| 并发模型 | `threading.Thread` + `queue.Queue` |
| 仿真通信 | 共享虚拟局域网总线 |
| 数据模型 | Python `dataclass` |
| 建议平台 | macOS、Windows 或 Linux |
| 启动方式 | `python main.py` |

依赖安装放在项目级虚拟环境 `.venv` 中，避免修改系统 Python：

```bash
python3 -m venv .venv
source .venv/bin/activate       # Windows 使用 .venv\\Scripts\\activate
pip install PySide6
python main.py
```

## 2. 需求分析

### 2.1 功能需求

#### FR-01 局域网拓扑

- 程序启动时创建 4 台默认主机，最多支持 6 台；
- 每台主机显示名称、IPv4 地址和 MAC 地址；
- 主机节点可在拓扑画布中拖动；
- 通过添加主机对话框加入第 5、6 台主机；
- IP 和 MAC 地址在局域网内必须唯一且格式合法。

#### FR-02 ARP 请求与应答

- 用户手动选择源主机和目标 IP，点击“发起 ARP 请求”；
- 源主机先查询本地缓存；
- 缓存存在且未过期时，显示缓存命中，不发送广播；
- 缓存未命中时，源主机广播 ARP 请求；
- 所有主机都收到广播副本；
- 目标 IP 所属主机发送 ARP 应答，且只单播给源主机；
- 源主机收到应答后完成地址解析并更新缓存。

#### FR-03 ARP 缓存

- 每台主机有独立缓存表，不共享缓存内容；
- 缓存记录目标 IP、目标 MAC、学习时间、最后更新时间和状态；
- 收到合法 ARP 请求或应答时，主机被动学习发送者 IP-MAC 映射；
- 同一 IP 的 MAC 变化时标记为“更新”；
- 条目超过可配置老化时间后自动删除，并在界面中显示“超时”；
- 缓存命中、写入、更新和删除都写入日志。

#### FR-04 可视化报文

- 广播报文使用“源主机 → 共享局域网总线 → 所有接收主机”的分阶段扩散动画；
- 单播报文使用“源主机 → 共享局域网总线 → 目标主机”的分阶段单播动画；
- 日志显示报文编号、类型、发送者 IP/MAC、目标 IP/MAC、传播方式和处理结果；
- 报文详情面板可查看最近一次选中的 ARP 报文。

#### FR-05 仿真控制

- 支持启动、暂停、继续和重置；
- 支持设置缓存老化时间，建议范围为 5～120 秒，默认 30 秒；
- 支持清空日志；
- 关闭主窗口时停止并回收所有主机线程。

#### FR-06 主机管理

- 支持查看选中主机的当前状态和缓存表；
- 支持编辑主机名称、IP 和 MAC；
- 修改主机地址后清理受影响的缓存，避免旧映射继续命中；
- 编辑失败时保留原配置并给出明确错误原因。

### 2.2 非功能需求

- 界面线程不直接执行阻塞式网络模拟，保证窗口可操作；
- 主机线程之间只通过消息队列交互，禁止直接调用其他主机的内部方法；
- 所有用户输入均进行校验，错误输入不得导致崩溃或死循环；
- 同一操作可重复演示，重置后状态应回到确定的初始状态；
- 关键协议逻辑与 GUI 解耦，便于单元测试和答辩解释；
- 事件日志可追溯完整时序，方便报告截图和现场排查。

## 4. 核心数据结构

### 4.1 主机配置

```python
@dataclass(frozen=True)
class HostConfig:
    host_id: str       # 稳定内部标识，例如 host-1
    name: str          # 显示名称，例如 Host A
    ip: str            # 例如 192.168.1.10
    mac: str           # 例如 AA:BB:CC:00:00:01
    x: float
    y: float
```

### 4.2 ARP 报文

```python
class ArpOpcode(Enum):
    REQUEST = "REQUEST"
    REPLY = "REPLY"

@dataclass(frozen=True)
class ArpPacket:
    packet_id: int
    opcode: ArpOpcode
    sender_ip: str
    sender_mac: str
    target_ip: str
    target_mac: str       # 请求时为 00:00:00:00:00:00
    source_host_id: str
    destination_host_id: str | None  # 广播为 None
    created_at: float
```

### 4.3 ARP 缓存条目

```python
class CacheChange(Enum):
    NEW = "NEW"
    UPDATED = "UPDATED"
    HIT = "HIT"
    EXPIRED = "EXPIRED"

@dataclass
class ArpCacheEntry:
    ip: str
    mac: str
    learned_at: float
    last_seen: float
    state: CacheChange
```

缓存以 `dict[str, ArpCacheEntry]` 存储，IP 地址作为键。缓存对象只允许所属主机线程访问；GUI 通过只读快照获取内容。

### 4.4 仿真事件

线程不直接修改 Qt 控件，而是向 UI 事件队列发送事件：

```python
class EventType(Enum):
    PACKET_SENT = "PACKET_SENT"
    PACKET_RECEIVED = "PACKET_RECEIVED"
    CACHE_CHANGED = "CACHE_CHANGED"
    HOST_STATUS = "HOST_STATUS"
    ERROR = "ERROR"

@dataclass(frozen=True)
class SimulationEvent:
    event_type: EventType
    timestamp: float
    host_id: str
    payload: dict
```

## 5. 虚拟局域网与线程模型

### 5.1 VirtualLanBus

`VirtualLanBus` 维护：

- `host_id -> Queue[ArpPacket]` 的接收队列映射；
- 总线锁，保护主机注册、注销和队列快照；
- 报文编号生成器。

核心操作：

```text
register(host_id) -> receive_queue
unregister(host_id)
broadcast(packet, sender_id)
unicast(packet, destination_host_id)
```

广播操作获取当前队列快照，然后把同一报文放入所有在线主机队列；单播只放入目标队列。总线不解析 ARP 语义，只负责传递。

### 5.2 HostThread

每台主机对应一个 `HostThread`，内部包含：

- 主机配置快照；
- 本机接收队列；
- 所属 `ArpCache`；
- 停止事件 `stop_event`；
- 暂停事件 `pause_event`；
- 发给控制器的事件回调。

线程循环：

```text
while not stop_event.is_set():
    如果处于暂停状态：短暂等待并继续
    检查并删除过期缓存
    从接收队列取报文（带超时）
    校验报文
    被动学习 sender_ip -> sender_mac
    根据 REQUEST / REPLY 执行协议处理
    发送 SimulationEvent 给控制器
```

### 5.3 暂停语义

暂停仿真时：

- 暂停接收报文处理；
- 暂停缓存老化计时的逻辑时钟；
- 保留当前画面、日志和队列内容；
- 继续点击“继续”后按原顺序处理队列。

为保证行为可解释，老化时间使用仿真时钟而不是直接依赖 GUI 刷新次数。

## 6. ARP 协议处理流程

### 6.1 发起请求

```text
用户选择 source_host 和 target_ip
             │
             ▼
控制器检查配置和仿真状态
             │
             ▼
源主机查询本地缓存
      ┌──────┴──────┐
      │             │
   有效命中       未命中
      │             │
显示 CACHE_HIT   构造 REQUEST
                    │
                    ▼
             VirtualLanBus 广播
```

请求报文字段：

- `opcode = REQUEST`；
- `sender_ip/sender_mac = 源主机地址`；
- `target_ip = 用户选择的 IP`；
- `target_mac = 00:00:00:00:00:00`；
- `destination_host_id = None`。

### 6.2 主机接收广播

每个收到请求的主机执行：

1. 记录 `PACKET_RECEIVED` 事件；
2. 校验发送者地址；
3. 被动学习发送者 IP-MAC；
4. 如果 `target_ip == self.ip`，构造 ARP 应答；
5. 否则只记录“非目标主机，忽略应答”。

### 6.3 发送应答

应答报文：

- `opcode = REPLY`；
- `sender_ip/sender_mac = 目标主机地址`；
- `target_ip/target_mac = 原请求发送者地址`；
- `destination_host_id = 原请求 source_host_id`。

目标主机通过 `unicast` 发送应答。源主机收到后再次学习目标 IP-MAC，并产生 `CACHE_CHANGED(NEW/UPDATED)` 事件。

### 6.4 目标不存在

广播完成后，控制器启动一次请求超时计时。若在超时时间内没有收到匹配应答：

- 日志显示“ARP 请求超时，未找到目标主机”；
- 源主机状态恢复为空闲；
- 不写入错误的缓存映射。

为配合协议过程可视化，虚拟链路单程投递延迟约为 1.4 秒，请求超时时间为 4 秒。同一源主机的相同目标请求在未完成期间禁止重复发送。

### 6.5 状态转换

```text
IDLE
  └─ 发起请求且缓存未命中 → BROADCASTING
       └─ 目标主机收到请求 → REPLYING
            └─ 源主机收到应答 → RESOLVED → IDLE
       └─ 超时 → TIMEOUT → IDLE
```

缓存命中路径为：

```text
IDLE ──缓存有效──> CACHE_HIT ──> IDLE
```

## 7. 缓存规则

### 7.1 被动学习规则

所有主机收到合法 ARP 报文时，均学习报文中的 `sender_ip -> sender_mac`，因此一次广播后不只有源主机能获得映射。这符合 ARP 主机通过观察报文更新缓存的常见实现。

### 7.2 新增与更新

- IP 不在缓存中：新增条目，状态为 `NEW`；
- IP 已存在且 MAC 相同：刷新 `last_seen`，状态保持有效；
- IP 已存在但 MAC 不同：替换 MAC，状态为 `UPDATED`，日志记录旧值和新值；
- 条目再次被使用：状态为 `HIT`，刷新 `last_seen`。

### 7.3 老化删除

每台主机周期性执行：

```text
if virtual_now - entry.last_seen >= aging_seconds:
    删除 entry
    发送 CACHE_CHANGED(EXPIRED)
```

老化检查周期建议为 200 ms。删除动作只由所属主机线程执行，避免并发修改缓存。

- 单播：绿色报文先从应答主机进入共享总线，再从总线移动到请求源主机；
- 总动画速度仍为约 1.3 秒，但内部拆分为“到达总线”和“离开总线”两个阶段；
- 动画中的报文端点实时读取节点/总线当前位置，用户拖动节点或总线时，正在播放的路径会跟随更新；
- 主机节点支持悬停高亮、双击编辑和右键设置源/目标，总线支持拖动，链路支持悬停高亮。
- 动画只表现已由总线投递的事件，不能用动画代替协议状态；
- 动画期间仍可查看缓存和日志。

## 9. 校验与异常处理

### 9.1 地址格式

- IPv4：使用 `ipaddress.IPv4Address` 校验；
- MAC：使用正则校验六组十六进制字节，统一转为大写冒号格式；
- 名称：非空，长度限制为 1～24 个字符。

### 9.2 配置冲突

- IP 重复：拒绝保存，提示冲突主机；
- MAC 重复：拒绝保存，提示冲突主机；
- 超过 6 台：禁用“添加主机”并提示上限；
- 运行中修改关键地址：弹窗确认后暂停仿真、更新配置、清理相关缓存，再恢复运行。

### 9.3 操作错误

- 未启动时点击请求：提示先启动仿真；
- 未选择源主机或目标 IP：禁用请求按钮或提示补全；
- 对自身 IP 发起请求：显示“本机目标，无需 ARP”，不广播；
- 重置过程中再次点击控制按钮：暂时禁用按钮，避免生命周期竞争。

## 10. 关键算法与复杂度

### 10.1 ARP 缓存查询

使用字典按 IP 查询，平均时间复杂度 `O(1)`。

### 10.2 广播投递

局域网最多 6 台主机，向所有接收队列投递一次，时间复杂度 `O(H)`，其中 `H` 为在线主机数。

### 10.3 缓存老化

每次检查遍历当前主机缓存，时间复杂度 `O(E)`，其中 `E` 为该主机缓存条目数。由于局域网最多 6 台主机，`E` 很小，周期检查不会影响界面响应。

### 10.4 报文处理

单个 ARP 报文处理只包含字段校验、一次缓存查询/写入和条件判断，平均复杂度为 `O(1)`。

4. 指出 Host B 返回单播应答；
5. 查看 Host A 缓存新增 `192.168.1.20 -> AA:BB:CC:00:00:02`；
6. 再次发起同一请求，展示缓存命中且没有广播；
7. 将老化时间改为 5 秒，等待条目过期并查看超时事件；
8. 再次请求，展示重新广播和重新学习；
9. 编辑 Host B 的 MAC，展示其他主机被动学习后的缓存更新；
10. 输入重复 IP、非法 MAC、未知目标 IP，展示错误提示和超时处理。

## 12. 测试方案

### 12.1 单元测试

| 编号 | 测试内容 | 预期结果 |
|---|---|---|
| UT-01 | 合法 IPv4/MAC 校验 | 通过并规范化 MAC 大小写 |
| UT-02 | 非法地址校验 | 返回错误，不抛出未处理异常 |
| UT-03 | 缓存新增 | 写入一条 `NEW` 条目 |
| UT-04 | 相同 MAC 再学习 | 刷新时间，不产生错误更新 |
| UT-05 | MAC 变化 | 替换并标记 `UPDATED` |
| UT-06 | 老化时间到期 | 删除并产生 `EXPIRED` 事件 |
| UT-07 | 总线广播 | 除发送方外所有队列均收到副本，发送方也可记录观察副本 |
| UT-08 | 总线单播 | 只有指定目标队列收到报文 |

### 12.2 集成测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| IT-01 | A 首次查询 B | REQUEST 广播，B REPLY 单播，A 缓存新增 |
| IT-02 | A 再次查询 B | 缓存命中，不产生 REQUEST |
| IT-03 | 缓存过期后查询 B | 条目删除，再次 REQUEST/REPLY |
| IT-04 | 查询不存在 IP | 广播后超时，无错误缓存 |
| IT-05 | 修改 B 的 MAC 后查询 | 地址合法保存，相关旧缓存清理并重新学习 |
| IT-06 | 暂停期间收到报文 | 报文保留在队列，继续后按序处理 |
| IT-07 | 添加第 7 台主机 | 操作被拒绝并提示上限 |
| IT-08 | 重置仿真 | 所有线程停止，拓扑和缓存回到初始状态 |

### 12.3 验收标准

- 连续运行 10 分钟无未处理异常、死循环或界面卡死；
- 4 台默认主机能够重复完成请求、应答、缓存命中和老化流程；
- 6 台主机时广播和单播目标不混淆；
- 暂停、继续、重置和关闭窗口后无残留工作线程；
- 报文日志字段与实际处理结果一致；
- 报告中的流程、截图和测试数据可由程序现场复现。
