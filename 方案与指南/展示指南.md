# ARP 地址解析协议仿真器展示指南

## 一、从 Finder 打开程序

1. 打开 macOS 的“访达（Finder）”。
2. 按 `Command + Shift + G`，打开“前往文件夹”。
3. 输入下面的路径并按回车：

   ```text
   /Users/feng/Documents/课程/计算机网络设计
   ```

4. 在文件夹中双击 `启动ARP仿真器.command`。
5. 终端窗口会自动打开，随后出现“ARP 地址解析协议仿真器”窗口。
6. 点击程序窗口左上角绿色按钮，将窗口最大化，方便老师观察动画、缓存和日志。

如果 macOS 第一次阻止运行，请右键点击 `启动ARP仿真器.command`，选择“打开”，然后再次确认“打开”。

也可以在终端中手动启动：

```bash
cd "/Users/feng/Documents/课程/计算机网络设计"
source .venv/bin/activate
python main.py
```

## 二、展示前准备

1. 确认界面右上角显示“4 台主机”和“未启动”。
2. 确认默认主机为 Host A、Host B、Host C、Host D。
3. 确认 Host A 的 ARP 缓存为空。
4. 保持默认缓存老化时间为 30 秒。
5. 展示开始前不要提前点击“发起 ARP 请求”，否则日志和缓存中会留下数据。

## 三、正式展示流程

### 第 1 步：介绍系统结构

先不要操作，向老师介绍界面：

> 左侧用于选择源主机、目标 IP 和控制仿真；中间是由 4 台独立主机构成的虚拟局域网；右侧展示当前主机的 ARP 缓存和报文详情；底部记录完整协议事件时间线。每台主机对应一个独立线程，共享局域网总线通过消息队列实现广播和单播。

可以拖动任意主机节点，说明拓扑节点支持交互。共享局域网总线也可以拖动，连接线会自动跟随更新。鼠标停留在拓扑框内时，可使用滚轮平滑缩放；放大后拖动空白处可以平移画布；双击空白处或点击拓扑栏中的“适应窗口”按钮可恢复 100%；点击“恢复默认拓扑布局”按钮可恢复所有节点和总线的位置。拓扑栏会实时显示缩放比例，范围为 100%～300%。

主机节点还支持快捷操作：双击节点打开编辑窗口；右键节点可选择“设为源主机”“设为目标主机”或“编辑主机”。这三个操作会直接同步左侧选择框，适合展示“拓扑节点和控制面板联动”。

### 第 2 步：启动仿真

1. 点击左侧“启动”。
2. 观察右上角状态从“未启动”变为“运行中”。
3. 暂停、继续、重置按钮随运行状态自动启用。

讲解：

> 点击启动后，程序为每台主机创建独立线程，并在共享虚拟局域网总线上注册各自的接收队列。

### 第 3 步：展示第一次 ARP 地址解析

1. 源主机选择 `Host A (192.168.1.10)`。
2. 目标 IP 选择 `192.168.1.20`，也就是 Host B。
3. 点击“发起 ARP 请求”。

应看到：

- Host A 变为广播状态；
- 橙色报文从 Host A 发送到其他主机，表示 ARP 请求广播；
- Host B 识别出目标 IP 属于自己；
- 绿色报文从 Host B 返回 Host A，表示 ARP 应答单播；
- 底部时间线出现 REQUEST、REPLY 和缓存新增事件；
- 右侧 Host A 的缓存出现 `192.168.1.20 → AA:BB:CC:00:00:02`。

动画会按“Host A → 共享局域网总线 → Host A～D”以及“共享局域网总线 → Host B → Host A”分阶段播放，整段速度保持不变，但每个阶段都有独立的路径、状态灯和日志记录。

讲解：

> Host A 在本地缓存中找不到 Host B 的 MAC 地址，所以发送广播请求。局域网中所有主机都会收到请求，但只有目标 IP 为 192.168.1.20 的 Host B 会单播应答。Host A 收到应答后建立 IP 到 MAC 的映射。

### 第 4 步：展示被动学习

1. 点击拓扑中的 Host C。
2. 查看右侧 Host C 的 ARP 缓存。

应看到 Host C 学习到了 Host A 的 IP-MAC 映射。

讲解：

> Host C 虽然不是请求目标，但它收到了广播报文，因此可以从 ARP 请求的发送者字段中被动学习 Host A 的地址映射。每台主机维护的是独立缓存，并不是共享同一张缓存表。

然后重新点击 Host A，以便继续观察 Host A 缓存。

### 第 5 步：展示缓存命中

1. 保持源主机为 Host A、目标 IP 为 `192.168.1.20`。
2. 再次点击“发起 ARP 请求”。

应看到：

- 不再播放广播和单播动画；
- 底部时间线只增加“缓存命中”事件；
- Host A 的缓存剩余时间重新开始计算。

讲解：

> 第二次解析时，Host A 已经有未过期的映射，因此直接命中缓存，不需要再次广播。这能减少局域网中的广播流量。

### 第 6 步：查看报文字段

1. 在底部时间线中点击一条橙色“ARP 请求”日志。
2. 右侧自动切换到“报文详情”标签页。
3. 指出请求报文的发送者 IP/MAC、目标 IP、全零目标 MAC 和广播目标。
4. 再点击一条绿色“ARP 应答”日志。
5. 对比应答报文中真实的目标 MAC 和单播目标。

讲解：

> ARP 请求时源主机还不知道目标 MAC，因此目标 MAC 使用全零地址表示未知；应答报文已经携带目标主机的真实 MAC，并且只单播回原请求主机。

### 第 7 步：展示暂停与缓存老化

1. 将缓存老化时间改为 `5 秒`。
2. 点击“应用老化时间”。
3. 如果 Host A 缓存已经过期，先再次查询 Host B，重新生成缓存。
4. 缓存出现后立即点击暂停图标。
5. 等待约 3 秒，指出缓存剩余时间不会继续减少。
6. 点击继续图标，观察倒计时恢复。
7. 等待缓存条目自动消失，底部出现“缓存超时删除”。

讲解：

> 每个缓存条目记录最后更新时间。超过配置的老化时间后，所属主机线程自动删除条目。暂停仿真时，报文处理和仿真时钟同时暂停。

### 第 8 步：展示不存在的目标

1. 点击目标 IP 输入框。
2. 按 `Command + A` 选中原内容。
3. 输入 `192.168.1.99`。
4. 点击“发起 ARP 请求”。
5. 观察橙色广播动画。
6. 等待约 4 秒，底部出现“ARP 请求超时，未找到目标主机”。

讲解：

> 所有主机都收到了广播，但没有主机的 IP 是 192.168.1.99，因此没有应答。源主机等待约 4 秒后判定请求超时，并且不会写入错误的缓存映射。

### 第 9 步：展示主机管理和容错

点击“添加主机”，输入：

```text
名称：Host E
IP：192.168.1.50
MAC：AA:BB:CC:00:00:05
```

保存后，界面右上角变为“5 台主机”，拓扑中出现 Host E。程序最多支持 6 台主机。

如需展示输入校验，可再次添加主机并填写已经存在的 `192.168.1.10`，程序会拒绝重复 IP。不要保存错误配置，关闭提示即可。

讲解：

> 添加或编辑主机时，程序会校验 IPv4 格式、MAC 格式以及 IP/MAC 的全局唯一性，错误配置不会进入仿真系统。

## 四、结束展示

展示完成后可以说：

> 本系统没有操作真实网卡，而是通过线程和消息队列建立可重复、可观察的 ARP 协议仿真。程序完整覆盖了请求广播、应答单播、被动学习、缓存命中、缓存更新、老化删除和请求超时，同时通过图形界面展示报文路径和缓存变化。

然后关闭主窗口。窗口关闭时，控制器会停止并回收所有主机线程。终端窗口会随程序退出回到命令提示符，可以直接关闭。

## 五、建议时间安排

| 环节 | 建议时间 |
|---|---:|
| 界面与架构介绍 | 40 秒 |
| 首次 ARP 请求/应答 | 1 分钟 |
| 被动学习与缓存命中 | 50 秒 |
| 报文详情对比 | 40 秒 |
| 暂停和缓存老化 | 1 分钟 |
| 未知目标与容错 | 50 秒 |
| 主机管理和总结 | 50 秒 |

完整展示约 6 分钟。如果老师只给 3 分钟，优先展示“首次解析、缓存命中、缓存老化、未知目标”四个场景。
